# Bank Fraud Detection Analytics Project
## Phase 1: Project Planning

### Problem Statement
In banks, fraudulent transactions are often identified manually after the fact, which is slow and allows losses to grow before anyone notices. This project analyzes transaction data to detect suspicious activity within seconds, flag it automatically, and reduce both financial losses and the time required to identify fraud.

### Objectives
1. Identify fraudulent transactions using historical data and pattern analysis.
2. Identify the time, amount, and location conditions under which fraud most often occurs.
3. Build SQL queries, Excel analysis, and Power BI dashboards to surface suspicious transactions.
4. Provide data-backed recommendations to help the bank reduce fraud losses.

### Scope
- **In scope:** Analysis of historical transaction-level data to detect and flag suspicious patterns.
- **Out of scope:** Building and deploying a real-time, production machine-learning fraud model.

### Key Performance Indicators (KPIs)
| KPI | Why it matters |
|---|---|
| Fraud Rate (%) | Shows what percentage of all transactions are fraudulent — a rising rate is a warning sign that fraud controls are failing. |
| Total Fraud Amount | Shows the total money lost to fraud — the direct financial impact. |
| Average Fraud Transaction Value | Reveals whether fraud typically happens in small, hard-to-notice amounts or large, high-impact ones. |
| Fraud by Transaction Type | Shows which channel (transfer, ATM, online) is riskiest, helping investigators focus their effort. |
| Fraud by Time of Day | Reveals if fraud clusters at certain hours, so monitoring can be increased during high-risk windows. |
| High-Risk Customer Segments | Shows which customer group is targeted most, helping the bank protect vulnerable segments. |
